## CH01-K001 操作系统、应用、硬件与内核的层次

第一批；原目录：1.1.1；草稿可导入。

学习目标：能够区分应用、操作系统与内核，解释受控资源访问。

来源：SRC-01，物理第11–16张；依据报告，原文件待核验。

### 先想一个问题

为什么桌面上的软件不都属于操作系统内核？

### 核心概念

操作系统在硬件能力和程序需求之间提供资源管理与服务；应用利用这些服务完成具体任务。内核是承担关键受保护功能的部分，不能把全部预装软件都归入内核。

### 理解原理与限制

从应用请求向下看，可依次讨论服务接口、操作系统对资源的管理以及硬件执行。层次图表达职责，不表示所有程序只能按一条固定的物理路径调用。

判断软件类别时，应看它承担什么职责、运行在哪一层，而不只看是否随系统安装。Shell、GUI与编译器并不因此必然成为内核模块。

### 例子与对照（教学补充）

保存文件时，编辑器组织文本；操作系统组织文件和设备访问；存储硬件完成实际读写。这是教学补充例子，不是课件原题。

### 易错点与边界

误解：凡是随系统安装的程序都是内核。纠正：安装方式不决定职责与特权级。
误解：内核就是整个操作系统。纠正：课程讨论中要说明采用广义系统还是内核口径。

### 学习小结

区分“应用做什么”和“操作系统如何提供受控环境”，再讨论内核的边界。

## CH01-K002 空分复用与时分复用

第一批；原目录：1.1.2；草稿可导入。

学习目标：能够根据资源划分方式区分空分与时分，说明适用限制。

来源：SRC-01，物理第18–20张；依据报告，原文件待核验。

### 先想一个问题

多项任务如何共享同一种资源？

### 核心概念

空分复用按空间或容量划分资源；时分复用让多个使用者在不同时段使用资源。二者可以在同一系统中共同出现。

### 理解原理与限制

空分关注“各自获得哪一部分”，时分关注“何时轮到谁”。例如内存分区强调容量划分，单 CPU 轮流执行任务强调时间安排。

|比较项|空分复用|时分复用|
|---|---|---|
|主要划分维度|空间或容量|时间段|
|典型观察|各区域由谁使用|当前由谁使用|
|仍需考虑|边界与访问保护|切换、调度和访问保护|

### 例子与对照（教学补充）

给 A、B 分别安排内存区域，同时让 CPU 先运行 A 再运行 B：前者是空分观察，后者是时分观察。具体容量和时长由教学示例设定。

### 易错点与边界

误解：时分意味着资源随时都能被抢占。纠正：能否抢占取决于资源和操作规则。
误解：共享等于没有隔离。纠正：共享仍需要保护与协调。

### 学习小结

先问划分的是空间还是时间，再检查资源是否允许切换与抢占。

## CH01-K003 资源抽象、虚化与复用

第二批静态草稿；原目录：1.1.2；草稿可导入。

学习目标：能够分别解释复用、抽象和虚化，而不把三个术语当同义词。

来源：SRC-01，物理第18、21–23张；依据报告，原文件待核验。

### 先想一个问题

为什么同一台打印机能接受多个程序的请求？

### 核心概念

复用让多个使用者共享有限资源；抽象用较简单的接口隐藏实现细节；虚化向使用者呈现逻辑资源视图。逻辑视图并不消除物理容量与处理速度的限制。

### 理解原理与限制

以打印服务为例：应用提交逻辑打印请求，不必直接控制设备寄存器；系统维护队列并安排单台打印机顺序工作。接受请求与设备完成输出是两个事件。

复用回答“如何共享”，抽象回答“如何隐藏复杂性”，虚化回答“向使用者呈现什么资源视图”。三者可能共同支持同一项服务。

### 例子与对照（教学补充）

P1 正在打印时 P2 提交请求，P2 可以进入队列，但不能因此被标记为已经打印完成。队列数据和故障情景属于教学补充。

### 易错点与边界

误解：虚拟资源不受物理资源限制。纠正：最终处理仍受设备能力与容量约束。
误解：排队成功就是打印成功。纠正：应区分接受、等待、执行和完成。

### 学习小结

用同一个打印案例分别解释三个问题，避免只背术语。

## CH01-K004 进程、虚存、文件三种基础抽象

第一批；原目录：1.1.2；草稿可导入。

学习目标：能够把执行、逻辑地址和持久数据分别联系到进程、虚存和文件。

来源：SRC-01，物理第24–31张；依据报告，原文件待核验。

### 先想一个问题

程序、地址和数据为什么需要不同的资源视图？

### 核心概念

进程组织程序执行所需的状态与资源；虚存组织程序可使用的逻辑地址视图；文件组织可持久保存的数据。三种抽象解决不同层面的问题。

### 理解原理与限制

进程不是一颗物理 CPU；虚拟地址不是物理地址；文件也不是某一固定磁盘位置的简单别名。操作系统负责把逻辑视图与底层资源联系起来，并检查访问权限。

|抽象|主要学习问题|不要混同|
|---|---|---|
|进程|谁在执行、保留什么状态|源代码或物理 CPU|
|虚存|程序如何使用地址空间|物理内存地址|
|文件|数据如何命名与持久组织|固定设备位置|

### 例子与对照（教学补充）

两个进程可以各自使用自己的地址空间，并通过文件接口访问数据；具体映射与访问权限由系统管理。本例为教学补充。

### 易错点与边界

误解：两个进程出现相同虚拟地址就一定访问同一物理位置。纠正：必须结合各自映射讨论。
误解：进程就是静态程序文件。纠正：进程还包含执行状态。

### 学习小结

分别用“执行状态、逻辑地址、持久数据”记住三种抽象的职责。

## CH01-K005 并发、并行、共享与随机性

第二批静态草稿；原目录：1.1.4；草稿可导入。

学习目标：能够区分时间区间内共同推进与同一时刻执行，识别共享资源协调问题。

来源：SRC-01，物理第35–39张；依据报告，原文件待核验。

### 先想一个问题

两个程序都在推进，是否表示它们同一时刻都在执行？

### 核心概念

并发关注多个活动在一段时间内共同推进；并行关注同一时刻的同时执行。单核交替可以形成并发，多核为并行提供条件，但不保证每时每刻都有多个任务执行。

### 理解原理与限制

共享资源可能使活动之间产生依赖或竞争，执行先后也可能受外部事件影响。课件“宏观并行、微观串行”需要结合单处理器教学语境理解，不能用来排除现代多核并行。

讨论一段时间轴时，先标注处理器数量，再标注每项任务的运行、就绪或等待状态，最后判断是否存在共享与协调需求。

### 例子与对照（教学补充）

单核：A[0,1)、B[1,2)、A[2,3)；双核：A 和 B 可以在不同核心同时运行。时间线由教学设计补充。

### 易错点与边界

误解：并发就是多核并行。纠正：观察维度不同。
误解：并发必然发生数据竞争。纠正：还需要分析是否共享数据及访问方式。

### 学习小结

判断并发看共同推进，判断并行看同一时刻与硬件执行条件。

## CH01-K006 单道与多道程序运行

第二批静态草稿；原目录：1.2.3；草稿可导入。

学习目标：能够沿 CPU/I-O 流程解释阻塞、就绪和多道程序减少闲置的条件。

来源：SRC-02，物理第13–17、20–22张；依据报告，原文件待核验。

### 先想一个问题

一个程序等待 I/O 时，CPU 为什么可能闲着？

### 核心概念

单道运行时，当前程序等待 I/O 可能使 CPU 闲置；多道运行时，系统可以安排其他就绪程序使用 CPU，从而减少部分空闲。

### 理解原理与限制

任务发出需要等待的 I/O 请求后进入等待状态；I/O 完成后回到就绪状态，等待调度。没有就绪任务时 CPU 仍然可以空闲。

利用率的改善取决于任务与设备的交替关系、可运行任务数量以及调度开销，不能承诺单个任务一定更快。课件的 35%/63% 时间线尚需回看原图，不能据报告摘录反推精确时长。

### 例子与对照（教学补充）

P1 发出 I/O 后等待，P2 若就绪可占用 CPU；若 P2 也等待且没有其他就绪任务，CPU 空闲。示例事件为教学补充。

### 易错点与边界

误解：多道程序让每个程序都更快。纠正：主要解释资源利用和整体推进，单任务等待可能增加。
误解：阻塞任务还能继续占 CPU 执行。纠正：等待完成前不能按就绪任务调度。

### 学习小结

沿“运行→等待→就绪→再调度”解释利用率变化，而不是只记百分比。

## CH01-K007 多道程序 CPU 利用率概率模型

第二批静态草稿；原目录：1.2.3；草稿可导入。

学习目标：能够使用 U=1-p^n，并说明独立等待和忽略开销的假设。

来源：SRC-02，物理第18–19张；依据报告，原文件待核验。

### 先想一个问题

增加程序数为什么在简化模型中可能减少 CPU 空闲？

### 核心概念

若 n 个程序各自处于等待的概率都是 p，且等待相互独立，则它们同时等待的概率为 p^n。把“至少一个可运行”作为 CPU 忙碌条件，可得简化利用率 U=1-p^n。

### 理解原理与限制

适用条件必须与公式一起说明：等待独立、概率口径一致、忽略调度等开销。这不是对真实系统负载的精确预测。

|p|n|U|
|---|---|---|
|0.8|4|59.04%|
|0.8|9|约86.58%|
|0|3|100%|
|1|3|0%|
|0.5|2|75%|

### 例子与对照（教学补充）

p=0.8、n=4：先计算 0.8^4=0.4096，再取补得到 0.5904。数值例子用于核验公式，不能解释为实测性能。

### 易错点与边界

误解：程序越多真实系统就一定越快。纠正：模型忽略开销，现实还受资源竞争等限制。
输入应满足 0≤p≤1，n 为正整数；非法输入不能继续计算。

### 学习小结

先检查假设，再计算“全部等待”的补事件。本轮先提供公式和核算表，滑块计算器尚待开发。

## CH01-K008 批处理、分时、实时系统

第一批；原目录：1.2.4；草稿可导入。

学习目标：能够根据交互方式与时间约束区分批处理、分时和实时系统。

来源：SRC-02，物理第25–31张；依据报告，原文件待核验。

### 先想一个问题

为什么“响应快”和“按时完成”不是同一个目标？

### 核心概念

批处理强调批量自动执行；分时强调交互响应和轮流服务；实时强调在规定时限内正确完成响应与处理。实际系统可以同时具有多种特征。

### 理解原理与限制

|类型|主要目标或约束|观察重点|
|---|---|---|
|批处理|批量自动执行、资源利用|提交后如何自动推进作业|
|分时|交互与及时响应|多个用户如何轮流获得服务|
|实时|明确时限约束|是否在规定时间内完成处理|

分类应结合工作方式和要求，不能仅凭“是否联网”“处理器是否快”判断。

### 例子与对照（教学补充）

课件用批发商店、零售商店、全天候服务作类比（SRC-02 42–43）。类比帮助记忆，但全天营业本身不构成实时系统的严格定义。

### 易错点与边界

误解：实时等于运算最快。纠正：核心是规定时限。
误解：三种类型绝对互斥。纠正：课件明确讨论混合特征。

### 学习小结

用“批量自动执行、交互轮流服务、明确时限”区分三种类型。

## CH01-K009 时间片轮转与分时服务

第一批实验导引；原目录：1.2.4；草稿可导入。

学习目标：能够解释 RR 队列、时间片和完成规则，并用实验检查结果。

来源：SRC-02，物理第27–29张；依据报告，原文件待核验。

### 先想一个问题

多个就绪任务如何轮流获得 CPU？

### 核心概念

RR 每次选择就绪队首，运行一个时间片或运行到完成。未完成任务重新进入队尾；已完成任务不再入队。

### 理解原理与限制

本平台复用 scheduler-1：同到达按输入顺序；时间片边界先把新到达者入队，再把未完成的当前进程放到队尾。没有就绪任务时显示 CPU 空闲。

实验是单 CPU、无 I/O、无切换开销的教学模型。课件给出分时与轮转思想；具体边界顺序和数值案例属于平台教学约定，等待你审核。

### 例子与对照（教学补充）

P1(a=0,b=5)、P2(a=0,b=3)、q=2：P1[0,2)→P2[2,4)→P1[4,6)→P2[6,7)→P1[7,8)。

|进程|完成|周转|等待|
|---|---|---|---|
|P1|8|8|3|
|P2|7|7|4|
平均周转7.5，平均等待3.5。本例为教学补充。

### 易错点与边界

误解：恰好完成也要再回到队尾。纠正：完成即离开。
误解：所有 RR 实现的同刻事件顺序天然相同。纠正：需先声明规则。
暂时空队列表示等待后续到达，不等于输入空进程列表合法。

### 学习小结

在关联 RR 实验中修改 q，先预测执行顺序，再对照同一引擎生成的甘特图。

系统“能做什么”与“选择怎么做”有什么不同？

### 易错点与边界

误解：机制与策略分离意味着两者必须在不同机器运行。纠正：首先是职责分离原则。
误解：换策略就不需要检查机制约束。纠正：选择仍受执行能力限制。

### 学习小结
