# 第一章新内容直接应用

用户已授权以已填写的新内容替换第一章，不再逐项审核。内容本身沿用第一章PPT-only包：15项知识内容、1项普通摘要（含12条）、4类关系图、4类静态流程图及1个RR实验。K012历史Linux代码不发布；尚未开发的动画不显示为可运行功能。

## 更新后会发生什么

1. 更新 `feat/development-foundation`，停止并重新启动后端。
2. 后端在已有数据库迁移完成后，查找唯一第一章和已有有效教师账号。优先依据教材章号1；没有明确章号时，只按明确的“操作系统概论/概述/概观”等标题匹配，不使用数据库ID=1猜测。
3. 成套备份数据库及受控文件到数据目录的 `backups/before-chapter01-apply-*`。
4. 在事务中导入内容、归档该章其他旧知识点、直接发布16项内容和所属小节及第一章。原课程必须已经公开，不自动改变整个私有课程的公开范围。
5. 用现有RR引擎实际重算规定示例，通过后发布RR教学实验。没有人工试运行/审核步骤要求。
6. 保存一次性应用记录。之后重启不会重新覆盖，也不会覆盖后来人工修改、撤回或新增的内容。

旧知识点的原ID、内容、修订、资料关联、题目关联、笔记、进度和实验记录不删除；旧知识点从当前学习展示中归档。其他章节和资料文件不变。需要完整恢复时使用备份恢复到新目录核对，不能直接覆盖正在使用的数据库。

旧版草稿包已经导入的情况会复用其知识点和实验ID；第一次应用按本次授权还原为规范新内容并发布。若其知识点或实验已跨章移动、RR算法或关键输入已发生变化，事务回滚并记录原因，不跨章覆盖。

## Windows启动

项目根目录：

```powershell
cd D:\A-bishe\OS-AI-Teaching-Assistant-System
git pull --ff-only
.\.venv\Scripts\python.exe -m uvicorn app.main:app --app-dir backend --host 127.0.0.1 --port 8000
```

另一个终端：

```powershell
cd D:\A-bishe\OS-AI-Teaching-Assistant-System
npm --prefix frontend run dev -- --strictPort
```

然后学生登录，访问 `http://127.0.0.1:5173/student/knowledge` 查看第一章。无需进入审核页面。

## 无法自动定位时

多个第一章、未有教师账号、课程尚未公开、目录归属发生异常或备份失败时，不猜测、不删除数据。教师端 `/teacher/chapter-content` 可查看应用状态。多课程场景可在那里明确选择目标章并直接应用，不需要逐项审核。

启动过程不创建默认账号或密码，不调用模型API。`CHAPTER01_AUTO_APPLY=0` 可显式禁用启动自动应用；普通隔离测试设置此值，专用测试单独启用并验证真实启动路径。

## 已验证的边界

- 直接应用后学生能读取全部16项内容和RR实验，旧知识点不再由新旧知识接口泄露到当前列表。
- 替换前的备份可以恢复旧知识点和笔记。
- 重复应用、重复启动不会产生重复内容或覆盖后续人工修改。
- 旧版草稿包可直接升级为已发布，无需重新录入。
- RR验证失败时，归档和发布一起回滚，保留原发布内容。
- 第一章编号可以对应数据库中非1的ID；多个候选不自动选择。
- 学生调用应用接口返回403；其他章节和资料记录保持不变。

四份PPT原件仍需在平台实际绑定；现有引用是报告给出的文件和物理页码，不能当成已完成视觉核验。此限制不阻止显示明确标记的概念重绘与讲解，不发布无法辨认的原始历史代码。
