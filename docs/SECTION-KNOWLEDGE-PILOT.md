# 一个小节、多份 PPT 的知识提炼试点

> 最新：导图/闪卡默认使用本文完整提炼流程，已取消手动开关，支持不选具体小节而整理本章相关课件。中间输入框已拆为真正直接问答。[最新说明](QUESTION-FIRST-REVIEW.md)。现已取消二次确认，选好资料与等级后点击工具直接生成。

2026-10-21。试点范围：在同一个已发布小节内，选择多份课件的对应页码，分批处理全部已选可提取正文，再共用知识生成思维导图和闪卡。沿用 React/FastAPI/SQLite，不引入新的大型框架、依赖或数据库迁移。

## 当前可用流程

1. 教师维护并发布章/节目录，上传资料；学生也可上传私人 PPT/PPTX、文字PDF或TXT。
2. 学生在智能问答先点击“新话题”，选择课程章（可选具体小节），勾选本小节相关的多份资料。
3. 展开“已选来源与页码范围”，逐份设置该小节的起止PPT页码。不要把整份400页课件全部当作一个小节。
4. 在学习设置选择讲解深度，点击右侧思维导图或知识闪卡。
5. 系统自动解析资料、校验范围并开始分批提炼，无需再次确认。超出页数或批次限制会显示提示；一次生成可能包含多次模型调用。
6. 过程展示当前阶段、批次和本次调用数。完成后查看知识依据，可跳到对应资料并核对标注页码。导图可调整显示比例，继续支持PNG/SVG/XMind导出。
7. 同一学生、同一小节与资料版本生成另一种成果时，复用已保存的知识；一般只再调用一次模型组织导图或提问。
8. 闪卡答案由其引用的知识结论组成，避免最终模型另写一套答案。每张卡的知识依据单独展示；可以翻面、切换、刷新恢复。
9. “下载试点报告”导出处理范围、阶段、知识、来源、调用数与指标。报告中的处理比例/引用比例不是知识正确率或考试覆盖率。

导图和闪卡默认使用完整提炼；知识讲解、测验、代码等仍沿用原快速检索接口，不被新多阶段流程替换。旧学习记录兼容。智能问答不恢复动画生成入口，独立算法实验保持原流程。

## 数据处理与质量检查

- 资料索引同时保留原快速片段与完整文字块。新版本索引可重建，原资料、上传文件、账号和教材内容不改写。
- 仅对显式、短目录页作保守规则标记；其他资料交给分批提炼阶段分类。无文字页明确列入未识别范围，不声称解析了图片、扫描件或图表。
- 全部已选正文块按最多6000字符、60块一批顺序处理，不使用前8块代替完整范围。长页拆成多个块以保留后续文字。
- 每批模型必须逐一返回所有输入ref，不允许漏块或重复块。正文块须有知识结论，非正文不得伪装成知识。
- 每条结论记录概念标题、知识句和逐字存在的资料摘录；引用不存在就失败。本检查能验证引用存在，不能证明模型的语义判断正确。
- 相同结论按去除首尾空白后的原文精确去重（保留数学运算符及大小写），保留多份证据；再由模型将事实分配为概念。合并必须覆盖全部fact ID，不能漏、重复或新增。语义相近的概念可以合组；当前不会保证所有同义改写结论都被自动去重。
- 模型报告冲突时停止成果生成，保留分析供核对。模型没有报告冲突不等于资料不存在冲突。
- 导图组织阶段仅返回主干与概念ID，叶子知识由后端从已验证结论构造，不让最终模型另写事实。
- 闪卡组织阶段仅生成问题与fact ID，答案由后端已有结论组成；校验问题不重复、引用有效、覆盖全部提炼概念。问题是否好答、是否泄露答案仍需要教学质量抽查。
- 每个关键结论记录逐页依据；原模块级引用保留兼容现有导出。

## 范围、调用与恢复边界

- 试点仍最多选择5份资料，限定同一课程；可选一个已发布小节，或整理本章相关课件。
- 最多120个已选物理页、12个分析批次、80条去重结论、20个概念。超限明确拒绝或提示缩小范围，不静默截取。
- 导图节点校验上限扩为120，以容纳主干、概念和知识句；普通快速模式仍按原提示建议较少节点。
- 首次通常为“分析批次 + 1次概念合并 + 1次成果组织”；当前最多14次调用。已缓存知识生成新成果通常只需1次。预计调用数不等于价格，具体金额取决于模型、token和服务商价格。
- 每个学生每天试点模型调用上限60次，失败/超时尝试也计入；原个人生成任务每日上限仍适用。不自动重试模型。
- 批次和合并结果保存在现有personal_ai_jobs.body_json.pilot中，每步保存检查点。失败时查看错误，明确选择可能计费的重新生成；新任务复用匹配的成功批次，失败批次重新调用。
- 单个任务仍在当前后端进程内执行，不是独立持久化任务队列。后端重启会中断运行，最后完成批次保留；心跳超过5分钟后旧任务标记中断，随后可手动恢复。换浏览器页面并不保证任务停止计费，应先查看任务记录。
- 原created_at不能判断多次调用任务是否超时，现使用持久化阶段心跳判断运行状态，避免长任务被误判后并发启动。

## 权限与缓存

缓存仅在同一学生内复用，指纹包含资料版本/范围、章/节、主题、处理版本、服务地址和模型；不缓存或返回密钥。预览与开始生成都重新校验来源权限，成果完成前再次核对权限和版本。换资料版本、页码、小节或模型后不误用旧知识。其他学生访问任务或进度返回404，教师访问学生个人工作区返回403。

当前仅在最近100条个人任务中搜索可复用知识；超出此范围可能重新分析。公共资料通用分析没有跨学生共享，属于后续优化，不引入私人资料串用风险。

接口沿用：

- `POST /api/student/personal/sources/preview`：`analysis_mode=section`，加chapter_id、section_id、sources、topic，返回`pilot_plan`，不调用模型。
- `POST /api/student/personal/generate`：单个map/flashcards，携带预览fingerprint、request_key和`analysis_confirmed=true`（前端自动完成范围校验后设置，无额外确认界面；缺少该兼容字段仍返回422）。
- `GET /api/student/personal/progress/{request_key}`：仅本人，展示阶段/完成批次/本次模型调用数。
- `GET /api/student/personal/jobs/{id}`：原接口返回成果及`body.pilot`报告。

## 新旧方案可复现对比

使用同一套人工编写的合成样例：两份真实PPTX文件，每份6页目录加4页正文，共20页；人工定义6条知识，两份材料之间重复2条。

```powershell
cd D:\A-bishe\OS-AI-Teaching-Assistant-System
.\.venv\Scripts\python.exe scripts\evaluate_knowledge_pilot.py --output docs\PILOT-COMPARISON.json
```

该脚本用独立临时数据库和确定性模型替身，不连接真实AI，不更改应用数据。结果见 [PILOT-COMPARISON.json](PILOT-COMPARISON.json)。

| 比较项 | 原快速概览 | 新试点 |
|---|---|---|
| 读取情况 | 8块，恰好都是目录 | 标记12块目录，处理全部8块正文 |
| 样例6条知识进入输入/结果 | 输入0/6 | 结果6/6 |
| 重复结论 | 此样例输入中无正文，不能评估去重 | 原始8条，去重为6条，保留多个来源 |
| 导图知识引用 | 未生成基线导图，不计算质量 | 6条结论全部进入图 |
| 闪卡 | 未生成基线卡，不能声称完成教学质量对比 | 6张，重复问题0张，答案对应人工样例结论 |
| 模型调用 | 仅计算了原取样，未调用生成 | 导图4次；复用知识后闪卡追加1次 |

这些数字证明工程流程能越过目录、覆盖所选正文、去重和复用。模型替身本来就知道样例答案，所以“6/6”不是DeepSeek准确率，不是学校课件验收结果。原方案未生成闪卡，因此不能据此宣布新闪卡教学效果更好。

真实课件下一步建议：选一个小节的2至3份PPT，人工列10至20个必学知识及重复项；保存快速模式和试点模式的成果，用同一份标准评估覆盖、错误、重复、问题可回答性，并记录实际调用时间/费用。页面可直接导出试点报告，无需再开发主流程。
