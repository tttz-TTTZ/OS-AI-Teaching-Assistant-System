# 检索优化第二步：减少提问套话干扰

2026-10-27。本文件为升级设计，尚未实现，不自动调用模型或改数据库。实践背景见[第一次技术记录](01-question-trace.md)。

## 目标与技术名称

让“请用一句话解释什么是磁道”优先寻找磁道知识，避免“什么是系统调用”仅因提问套话而排到前面。

本阶段涉及：查询预处理（query preprocessing）、词项分析（tokenization）、可解释的关键词检索、信息检索评测及回归测试。它属于RAG的检索优化；不要求先上LangChain、Agent、Redis或向量数据库。

## 第一步：先证明哪些词造成干扰

在隔离测试或本地调试中保存：原问题、检索词、候选片段的命中词、各词贡献、总分和资料/页码。由此解释排序，而不是看到正分就猜原因。

默认服务日志保持只有模式、数量、分数，不扩大为记录学生问题和课件正文。命中词若进入调试工具，也可能暴露问题内容；只能显式在本地测试中使用，不默认向其他学生、公共日志或浏览器返回未授权资料。

验收：能用实际命中词解释一个偏题例子；保留原来的权限、页码范围、同分顺序和零分过滤。

## 第二步：原问题和检索查询分开

保留original_question交给模型理解完整需求；另外生成retrieval_query用于寻找依据，不直接重写或丢弃用户问题。

采用保守、可回退的固定提问模板清理。例如完整匹配“请用一句话解释什么是……”时，尝试提取后面的概念。只在句首/完整模板上处理，不全局替换词语。

| 原问题 | 期望保留的检索内容 | 注意 |
|---|---|---|
| 请用一句话解释什么是磁道 | 磁道 | 不因“什么是”命中系统调用页 |
| 什么是系统调用 | 系统调用 | 保留整个概念 |
| 什么是解释程序 | 解释程序 | “解释”是术语的一部分，不是应全局删除的停用词 |
| 系统调用和普通函数调用有什么区别 | 两个完整概念及比较意图 | 不只留下其中一个对象 |
| 为什么TLB未命中不一定缺页 | TLB、未命中、缺页、否定关系 | 不能删掉“不”而改变问题 |
| RR时间片结束时如何处理新到达任务 | RR、时间片、到达等核心内容 | 英文缩写要保留 |

这些是待验收的设计目标，不是声称已有可靠概念识别器。无法确定时保留原查询；清理后为空则回退，不能拿空查询检索所有资料，也不能偷偷换成概览。

首轮不做“通用词黑名单全局删除”，不把所有解释/为什么/不等表达都视为无意义内容。中文双字切片会产生跨边界词，删除几个词不保证完全消除噪声。

## 第三步：先比较，再决定是否换检索算法

建立至少10个固定问题，逐步扩到30个。每题记录所选文件、物理页、可支撑回答的片段、预期要点、资料是否缺失及典型偏题页。

至少包括：直接定义、提问套话、概念对比、否定问句、英文缩写、无相关资料、概览请求和私人资料越权。

在同一批资料/页码下比较：

1. 当前双字词加权检索（零分过滤后的基线）。
2. 基线加保守查询预处理。
3. 只有证据显示需要时，再尝试BM25；它仍是词项检索，不能宣称会理解定义。

标注与指标：

- Top-3正确依据命中率：前三条是否包含人工确认的正确依据。
- Precision@3：前三条中相关依据的比例，预先定义不足3条的计量规则。
- 无依据处理：是否误把偏题片段当作课件依据，而不是仅检查HTTP状态。
- 答案支持度：逐条检查回答结论是否由引用支撑，与“检索到正确页”分开评估。
- 响应耗时：固定环境记录，不编造性能增益。

没有人工标注和实际对照前，不写“准确率提高XX%”。固定样例通过也不能等同整门课程已验证。

## 保留与失败处理

- 资料访问、所属课程、物理页范围、正文长度预算、指纹一致性检查保持。
- 资料概览和完整小节提炼是独立模式，不套用普通提问的查询规则。
- 对资料无法支持的问答，保持明确的通用知识标注；教师正式出题等严格依据流程不能被同样宽松回退。
- 图片/扫描代码仍有解析限制；查询预处理不能解决没有读取到图片内容的问题。
- 重排序、Embedding、向量数据库和语义支持度检查属于后续候选，不在本阶段标为已实现。

## 建议涉及的文件

- `backend/app/personal_sources.py`：词项分析、查询预处理与排序，优先做小改动。
- `backend/app/personal_chat.py`：保留原问题，传递独立检索查询（确有需要再改）。
- `backend/tests/test_retrieval_filter.py`或新的独立用例：真实检索对照、例外词和权限回归。
- `docs/learning/`中的问题清单和实验结果：保存固定样本、失败项和升级结论。

不先改模型密钥、数据库、教师内容或批量重建索引。查询策略如影响已保存任务的结果，应核对指纹与旧任务兼容性，不把旧答案重新生成覆盖。

## 对应学习顺序

1. 巩固列表、字典、Counter、函数与条件分支。
2. 理解中文双字切片、英文词项以及词频/片段频率。
3. 学习正则表达式中的句首匹配和完整模板，理解过度清理的风险。
4. 编写固定输入的pytest测试，区分单元实验、真实接口测试和模型质量评测。
5. 比较测试结果，再学习BM25与向量语义检索；不一次引入所有技术。
