# 知识点学习模块升级：需求、功能与边界分析 V1.0

日期：2026-10-16（北京时间）  
状态：需求设计稿，供用户审阅；没有实施业务代码或数据库迁移。  
依据：本次用户上传的《第一章 1.1〈操作系统概观〉交互式数字教材正式教案 V1.0》全文及现有仓库源码。附件中的“后续实现规格”作为待设计需求，不能作为已完成功能的证据。

## 1. 工程结论

目标是可持续编辑、可发布版本、可阅读、可交互、可跳转练习的数字教材模块。保留 React + FastAPI + 关系数据库，不重建工程，也不为每个知识点编写单独页面。

建议采用“课程—章—节—知识点—内容块”的结构：知识点由教师配置，图文与场景通过受控模板呈现，复杂交互由工程师开发组件、教师填写教学参数。不能承诺教师上传任意动画代码即可安全运行，也不能把播放视频等同于参数可调的模拟实验。

本报告覆盖教案全部12个知识点、10类内容模块、6组重点交互、其他轻量交互、练习联动、学习状态和发布流程。所有下面标为“应实现”的能力均为下一阶段需求，不是本轮交付完成声明。

## 3. 教案需先澄清的事实

1. 教案标题是第一章的1.1节，不是第一章完整内容。12个知识点只是1.1的教学单元，不能据此覆盖掉第一章其他小节或前七章课程目录。
2. 教案使用《操作系统概论》的称呼；此前用户确认的教材是费翔林、骆斌《操作系统教程》第5版。当前未提供本节原PPT和完整教材，暂以此前书目信息建来源，正式录入前核对书名、版次及PPT页码。
3. 教学编号1.1.1—1.1.12与原教材目录中可能同名的编号不能混为一谈。分别保存“平台教学编号”和“教材原始节号/页码”。数据库ID也不能作为教学编号。
4. 12项建议时长合计110分钟，与90—120分钟范围一致。它是建议，不是已学习时长或完成门槛。
5. “6个重点交互”指6组优先模板，组内可能有多个场景；不能只开发6个页面而遗漏其他知识点的轻量交互。
6. 历史Linux代码规模教案给出约639.9万行，但分类柱状图缺少可核验的分类数值。不得自行编造分类数据或现代版本数据。

## 4. 模块职责与跳转

| 板块 | 承担职责 | 与知识学习的连接 |
|---|---|---|
| 知识点学习 | 目标、问题导入、概念、原理、案例、易错点、情境图解、内嵌教学模拟 | 课程学习的主入口 |
| 章节练习 | 统一题库、正式作答、批改/自评、解析、错题与历史记录 | 按当前知识点或小节筛题，完成后返回原学习位置 |
| 算法实验 | 独立参数实验、详细运行轨迹、算法比较；保留FCFS | 对需要深入实验的内容提供“展开完整实验” |
| 课程资料 | 教材、PPT导出PDF、讲义等来源与附件 | 在知识点直接定位资料/页码，鉴权复用 |
| 智能问答 | 在已有能力上支持围绕当前知识点提问的入口 | 选配关联上下文，不冒充已实现RAG或自动判分 |

正文保留“观察、切换、拖动、运行、比较”的学习交互，不在正文复制一套评分系统。正式单选、多选、判断、简答，以及需要记录对错的匹配/分类/设计决策题，统一交由练习板块。分层拖拽可以作为不计分探索；若教师要计分，则以相同组件生成练习活动，结果只在练习服务保存。

建议知识点正文中在相关段落之后放置小型互动，右侧只放快捷入口/资源；避免把所有动画压到独立“动画区”，或在阅读右栏放多个不断播放的窗口。

## 5. 学生端需求

### 5.1 目录与页面

- 左侧：章—节—知识点目录；支持收起、当前项高亮、前后知识点、搜索标题/术语、重点/难点标签。
- 中间：知识点标题、编号、建议时长、目标；按教师顺序展示内容块；块锚点可直达。
- 右侧：本页大纲、相关资料与页码、先修/后续知识、交互与练习状态、当前知识点练习入口。
- 窄屏将目录/大纲折叠；先保证桌面。提供字号调整、键盘操作、非颜色唯一标识、减少动画偏好。
- 首页/小节概览显示真实内容和上次学习位置；无记录时显示“开始学习”，不展示虚构掌握率。

推荐的正文顺序：学习目标 → 问题导入 → 核心概念 → 原理及随文交互 → 典型案例 → 易错点 → 总结 → 去练习 → 扩展资料与关联知识。教师可以调整原理、交互、案例的相对顺序；必需模块仍由发布规则校验。

### 5.2 学习过程

1. 进入知识点，读取已发布版本和本人学习记录。
2. 阅读到指定块，支持手动“标记已阅读”；滚动和停留只做辅助信息。
3. 完成教师要求的互动观察任务，如分别运行有锁/无锁场景并观察结果。
4. 点击“练习本知识点”，携带知识点、已发布版本、返回块定位。
5. 作答后查看解析和错题，可从解析回到对应正文块。
6. 返回知识学习页，刷新真实练习状态；可以继续下一个知识点。

刷新、跨设备登录、网络重连后恢复最近成功保存的位置。页面内滚动可先本地缓冲，服务端按间隔/离开前保存；显示“保存中/已保存/未同步”，不能仅依赖关闭页面时的请求保证保存。

### 5.3 四种学习状态

| 状态 | 证据 | 禁止的推断 |
|---|---|---|
| 已阅读 | 学生主动标记及已保存阅读位置 | 打开页面不等于读完 |
| 已完成交互 | 完成指定观察步骤，保存参数、组件版本和事件摘要 | 点击播放不等于理解；无交互时显示“不适用” |
| 已完成练习 | 后端已保存规定题组的有效作答 | 点开练习页不等于完成 |
| 已掌握 | 区分“自评掌握”和“达到客观练习标准”；显示依据/版本 | 没有充分证据或简答仅自评时，不声称系统已证明掌握 |

四项为独立维度；学生可以先练习再阅读。知识点概览可派生“学习流程已完成”，但不能把它等同于掌握。自评可以撤销，客观标准由教师配置并公开说明。后续发布实质新版本提示“内容已更新，建议复习”，保留旧版本记录；不能悄悄清空成绩。

书签、个人学习笔记、标记“仍不理解”作为增强功能；笔记默认本人可见，教师不能直接读取。教师反馈收集应是学生明确提交的反馈，和私人笔记分开。

## 6. 教师端需求：能长期维护的内容工作台

### 6.1 列表与目录

支持按课程/章/节、标题、教学编号、发布状态、缺少资料、缺少题目筛选。提供新增、复制为草稿、编辑、排序、预览、发布、撤回、归档。复制生成新ID，不共享可变草稿；任何复制内容默认草稿。

章节已有排序继续复用；新增小节与知识点排序。排序、移动保持稳定ID，更新显示编号时提醒教师，旧链接按ID仍可访问。禁止跨课程混挂，禁止先修关系形成环。

### 6.2 教学基本信息

课程/章/节、教学编号、标题、摘要、关键词、重点/难点/拓展、建议时长、学习目标、先修和后续知识、教材/PPT来源、内容审核备注。建议时长是正数建议，不对学生强制计时。

先修是推荐导航，初版不强制锁定学习路径，避免无记录时挡住学生。

### 6.3 结构化内容块编辑

| 教学模块 | 支持内容 | 发布规则 |
|---|---|---|
| 基本信息/目标 | 多条目标、标签、建议时长 | 必需 |
| 问题导入 | 场景、问题、配图 | 必需 |
| 核心概念 | 定义、术语、中英文、强调 | 必需 |
| 原理精讲 | 多段标题、列表、表格、代码、图解 | 必需 |
| 图解与交互 | 图片/流程图、受控动画模板、参数 | 按教案需要；不适用可明确说明 |
| 典型案例 | 情境、过程、解释、关联模块 | 必需 |
| 易错点 | 误解、正确解释、反例 | 必需 |
| 自测练习关联 | 题目/题组、题型、数量、练习目标 | 正式发布必需，作答在练习板块 |
| 扩展阅读 | 教材页码、PPT页码、公共资料链接 | 可选，但引用必须有来源 |
| 知识关联 | 先修、后续章节/知识点 | 必需，根节点可标“无先修”，不能要求填假链接 |

编辑器提供“添加块、移动、复制、删除、折叠、草稿保存、学生视角预览”。第一版采用左目录、中间块编辑、右侧属性/校验；上下移动按钮即可，不把复杂拖拽作为上线前提。

富文本用成熟的安全编辑/渲染方式或带预览的Markdown，不自行开发完整排版引擎。教师看到表单和预览，不要求手写HTML/JSON。支持段落、标题、粗体、列表、表格、代码、受控链接、图片及图注；数学公式为增强项，不阻塞本教案。资料PDF用阅读链接，不把扫描PDF直接当可交互正文。

### 6.4 图片与其他媒体

- 图片：PNG/JPEG/WebP，实际格式校验、尺寸/体积上限、替代文字、图注、来源；建议初始单张≤10MiB，另限制像素和解码开销。
- 图表：教师填写标签/数值/单位/版本/统计口径及来源；无数值时不给假图。工程绘制的图形受控渲染。
- 视频可作为补充讲解，不能代替必须可调参数的互动；初版优先图文和模拟器，视频上传/转码不设为核心验收前提。此教案本身没有要求视频。
- 不允许上传任意JS、HTML、可执行SVG或跨站嵌入页当“自定义动画”。普通图片上传不能沿用150MiB公共PDF上限。
- 来源元数据至少包含书名/作者/版次或PPT名称、印刷页码与PDF页序、来源文件版本、备注。替换资料后保留原引用版本或标注待核对。

### 6.5 动画配置

教师选择组件模板 → 选择场景 → 填入参数/说明 → 预览运行 → 校验 → 保存草稿。可配置进程名、到达时刻、CPU时长、内存大小、任务队列、初始计数、事件延迟、预设交错顺序、默认速度、观察任务和解释文本。

组件代码与参数分离。教师能改内容和已有模板支持的参数；新增一种原理/交互规则需要工程师增加受控模板，不承诺任意动画零代码生成。修改某知识点配置不改变其他知识点；组件升级保留版本或提供兼容迁移。

### 6.6 练习编排与教学反馈

教师可以从现有题库挑选、关联一个或多个知识点/内容块、设置顺序和题组；在题库管理单选、多选、判断、简答及需要的匹配/分类题。知识点编辑器显示题型、是否已发布、答案/解析是否完整，不重复保存另一套题库。

客观题按规则判分；简答提供学生文本作答、参考答案、要点、自评，可选教师人工评阅。未人工评阅时明确“待评阅/仅自评”，不做伪自动评分。多选默认完全匹配得分，部分得分如需启用必须明确规则。

教师可查看真实的阅读/交互/作答完成情况、客观题正确率与主动反馈；没有数据时显示空状态，小样本只显示人数与原始计数，不画伪掌握率图。

## 8. 动画与实验的工程规格

### 8.1 通用播放器

统一支持开始、暂停、继续、单步、上一步/拖动回放、重置、倍速、当前状态、解释面板、事件日志。单纯点击展开的结构图不强行出现时间播放器；真正有事件序列的组件必须提供。

事件序列由状态模型生成，前端播放器只推进和渲染。建议事件字段：seq、模拟时间、事件类型、主体、资源、状态变化、教学解释键。单步与自动播放必须产生一致结果；倍速只改播放节奏，不改模拟时间与计算结果。

随机场景保存种子和输入，允许“相同参数复现”和“换一种合法顺序”。回退通过事件重放/快照恢复，不能靠倒放CSS动画。参数修改后提示“需要重新运行”，不能将旧结果配新参数展示。

输入和事件总量有上限；建议初版≤20进程、≤2000事件，详细阈值在模板规格中定；必须校验有限数、范围、ID唯一、依赖关系、锁状态、内存总量，不能只校验界面输入。

### 8.2 六组模板及更细边界

| 组 | 包含场景 | 特有边界 |
|---|---|---|
| A P0 资源复用 | 连续内存分配 + 单核时间共享/设备独占 | 容量不足/零分配/空闲；不静默裁剪；时间共享示例与FCFS不混淆 |
| B P0 虚拟打印与抽象 | 入队/出队/处理、逻辑请求到物理设备 | 空队列、连续添加、重复任务、处理中不重复执行；只是模拟，不操作真实打印机 |
| C P0 单双核时间轴 | 到达、运行、就绪、阻塞、恢复、切换开销 | 同时到达确定性打破平局、空闲、全阻塞、同一任务不同时占多核；CPU/I-O可重叠需说明 |
| D P0 共享变量 | 合法交错读改写 + 互斥 | 保留每进程内部次序、锁独占、等待不得写入、边界不越步 |
| E P1 分层与资源图 | 职责点击、请求路径、分类、五模块事件联动 | 组件可跨多模块，广义狭义解释，不用一条固定流水线误导所有程序 |
| F P1 异步事件 | 时刻、延迟、依赖、等待队列 | 时间单位统一、延迟非负、不可违反因果依赖；无效参数解释拒绝 |

四视角、五目标、管理员/服务员、历史模块图为轻量模板/同一图形组件的不同配置，仍需完成。虚拟地址示意需要实现概念映射，不要求本轮开发分页置换算法。

完整算法实验与正文内模拟可以复用“事件模型+渲染器”，各自配置复杂度不同。FCFS保留原接口和回归，不把时间片轮转假装成FCFS。若结果需要用于正式成绩，由后端按受控参数/种子复算或验证，不能信任前端上报的“已掌握=true”。

## 9. 数据库与版本设计建议

继续单一关系数据库。以下是逻辑模型，后续设计评审后再定DDL，避免一次创建所有预留表。

| 对象 | 建议字段/职责 | 兼容策略 |
|---|---|---|
| sections 新增 | chapter_id、教学编号、标题、排序、状态 | 节不替换原章，旧知识点可暂不归节 |
| knowledge_points 扩展 | section_id可空、教学编号、摘要、排序、当前草稿/发布修订ID、归档标记 | 保留原ID、chapter_id、content、lab_path及旧关联 |
| knowledge_revisions 新增 | point_id、版本号、结构化blocks_json、schema_version、学习目标/来源/模板参数快照、编辑人、时间、基础版本 | 草稿可更新；发布后的版本不可原位改写 |
| knowledge_links 新增 | 源/目标知识点、关联类型、排序 | 先修禁止环，相关知识可双向，不把关联当硬学习锁 |
| knowledge_assets 新增 | 受控存储名、真实类型、大小/hash、来源、图注、替代文字、上传者 | 图片等与原PDF/TXT分开校验；同一数据根目录备份 |
| revision_assets 新增 | 修订/媒体引用关系 | 用于草稿/发布权限判断、引用检查和保留旧资产 |
| knowledge_question_links 新增 | 知识点/题目、块ID、顺序、要求 | 一题可关联多个知识点；检查同课程 |
| questions 扩展与题目修订 | 题型、结构化选项/答案/规则、修订版本 | 旧answer整数单选继续兼容；旧题不擅自变多选 |
| practice_attempts / answers 新增 | 本人ID、知识点/课程、发布内容/题目版本、题目快照、答案、评分/自评状态、时间 | 留存作答依据；新题答案不能重写旧成绩 |
| knowledge_progress 新增 | user_id、point_id、revision_id、块定位、阅读、自评、交互/练习摘要、更新时间 | 独立维度/唯一键；禁止依赖sessionStorage充当持久记录 |
| interaction_runs 新增 | 本人、内容块/修订、engine_version、参数/种子、完成步骤、结果摘要 | 限量保存，不无限上传播放帧；事件记录可复现 |
| content_publication_events 新增 | 发布/撤回/回滚、操作者、前后修订、理由、时间 | 与账号审计区分；记录谁推送了什么 |

笔记/书签增强阶段可新增用户注释表，不在初版强行加入复杂全文批注与协作系统。

内容块采用“关系表保存主体、版本与引用 + 有版本号的结构化JSON保存块内容”，不为每段文字单建表，也不再把所有内容塞进不可拆的大字符串。每块保存稳定block_id、type、schema_version、payload；移动顺序不换ID。后端按类型校验，未知类型不能直接发布。

媒体文件本体继续在受控目录，数据库存元数据和引用。发布内容应引用具体资产版本，不把同名文件覆盖。备份/恢复必须覆盖数据库、图片、原资料、历史版本依赖；不能只备份SQLite。

## 10. 草稿、发布与持续更新

1. 新建/复制是草稿，不影响学生当前页面。
2. 教师编辑、保存，记录编辑人和时间；自动保存只作用草稿，显示失败与重试。
3. “学生视角预览”复用阅读渲染器，但通过教师鉴权接口读取草稿，显示预览标识。
4. 发布前校验必需内容、资料可用性、组件参数、题目与来源、章节状态。旧知识点标记“待补充”的地方不能悄悄当完整新教材验收。
5. 发布事务原子切换 published_revision_id，同一次读取得到一致版本。用户正在读旧版时提示新版本，不自动跳回顶部。
6. 再次编辑建立新草稿，学生继续看上一个已发布版本。
7. 撤回使学生列表、详情、文件直链、AI引用都停止取得相关未发布内容；受控文件仍保留。不能撤销学生已经下载的本地副本。
8. 历史版本可比较、回滚；回滚生成新的发布事件，不篡改历史时间与内容。
9. 两教师同时编辑用revision/ETag校验，冲突409并保留待保存草稿，不允许最后保存者无提示覆盖。
10. 有学生作答或其他点引用的知识点只归档/撤回，不做级联物理删除；内容重大变更提示重新学习，旧学习记录保留。

## 11. 练习联动的最低升级范围

本教案有单选、多选、判断、简答/情境题，现有单选接口无法完整覆盖。必须同时增量升级题库，不能只在知识点页面增加一个原有章节练习链接就算完成。

建议入口参数包含知识点ID和返回块ID，服务端按权限返回当前可用题组，返回路径由站内白名单生成，防止任意外部重定向。示例导航形态：`/student/practice?knowledge=42&block=principle-2`，完成后用保存的学习来源返回知识点；具体命名在实现阶段统一。

支持未作答/部分作答、刷新草稿恢复、重复提交幂等、重新练习建立新attempt、参考答案何时开放、已撤回题目的处理。学生取题接口不返回标准答案；判分/参考答案通过授权提交后的接口提供。简答自评不计入客观正确率，教师未评不冒充已评分。

同一知识点少量12题样例可以先验证题型，但正式“掌握”判断需要教师确定题量与标准，不能凭一道记忆题给出高可信掌握率。

### 11.1 建议接口职责（设计，不是当前已有API）

现有 `/knowledge`、`/knowledge/{id}` 优先扩展并兼容，不另起一套课程服务。列表只返回目录/摘要，详情按需要取已发布内容，避免一次拉取全课图片和大正文。

| 接口组 | 建议职责 | 后端约束 |
|---|---|---|
| 学生课程目录/知识详情 | 返回章/节/点摘要、完整发布修订、块锚点、可见关联 | 每次核对课程/章/节/点状态，学生不能通过revision参数拿草稿 |
| 教师知识草稿/预览 | 保存结构化草稿、预览、复制、排序、差异 | 教师鉴权、CSRF、参数白名单、编辑版本冲突409 |
| 教师发布操作 | 校验、发布、撤回、历史版本、回滚 | 独立发布动作、审计、事务，保存不能隐式发布 |
| 内容资产上传/读取 | 校验与存储，教师草稿预览，学生已发布引用读取 | 原文件名不当路径；图片不得挂静态目录；按引用版本授权 |
| 本人学习记录 | GET/PUT 本人点/块位置、阅读与自评、同步版本 | user_id来自会话；不能写他人进度；不得直接接受客户端客观掌握结论 |
| 互动运行记录 | 提交参数、种子、引擎/内容版本及观察任务证据 | 白名单、数量限制、证据校验；正式评分需要服务端复算 |
| 练习题组/作答 | 按知识点过滤、保存草稿、提交、取本人历史与错题 | 重复提交幂等、保留题目快照、答案字段分视图返回 |
| 教师学习反馈 | 实际完成计数、客观题错误情况、学生主动反馈 | 课程授权范围；不返回学生私人笔记 |

发布修订中的教师说明、评分规则、练习答案应有独立私有字段/服务端视图，不能把教师完整JSON原样发给学生再靠前端隐藏。学习正文引用的简答“参考答案”也应作为练习反馈管理；若教师有意将案例分析直接公开为教学正文，应和正式测验明确区分。

## 12. 边界与失败场景清单

| 场景 | 应有行为 |
|---|---|
| 无章/节/知识点 | 学生空状态；教师可创建；不返回演示假内容填充 |
| 章或节撤回、归档 | 学生所有入口和直接API同步拒绝；已登录教师可管理 |
| 学生拿草稿ID/媒体ID/别人的记录ID | 后端授权拒绝；不可仅靠隐藏按钮 |
| 正文引用学生个人资料 | 发布校验拒绝，不把私人资料变成公共附件 |
| 正文不完整/组件缺失 | 草稿可保存，发布指出缺项；学生看到故障块提示与替代文字 |
| 参数无效或极大 | 前后端校验，清楚提示；不无限动画、无限事件、浏览器卡死 |
| 图表数据缺少 | 显示待补齐/不发布该图，不编造统计 |
| 保存断网 | 草稿保留、标未同步、可重试；不假显示成功 |
| 上传中断/磁盘满 | 不发布坏资产，不留有效DB记录指向不存在文件；可重试 |
| 图片撤回/替换 | 已发布修订仍固定引用旧资产或明确撤回；不能静默改变旧教材 |
| 内容块排序/删除 | 稳定ID保留；旧阅读定位失效时回到相邻块或知识点顶部并提示 |
| 多教师编辑 | 冲突检测与差异提示，不覆盖无提示 |
| 多学生/同浏览器多账号 | 用户ID来自后端会话；缓存按账号/版本区分，退出清理私人状态 |
| 知识点换章/换节 | 同课程内检查引用和编号；已发布移动需确认，跨课程不默认允许 |
| 题目修改/撤回 | 新练习读新版本；历史attempt保留当时题目/答案；已撤回敏感内容不通过新入口泄露 |
| 学习状态重复同步 | 幂等写入；离线旧状态不得覆盖较新进度，掌握自评撤销允许明确操作 |
| 当前页面长时间停留 | 会话过期提示重登；恢复后确认内容版本，再续传本人未同步信息 |
| 视频/动画无法播放 | 提供静态图、事件表、文字说明，不据播放故障判学生未理解 |
| 跨站内容/恶意脚本 | 受控渲染、URL白名单、文件实际类型检查；禁止任意iframe与JS |
| 成绩与隐私 | 教师只按课程授权查看学习/作答数据；学生只读本人记录；默认不开放私人笔记 |

当前教师权限是统一课程管理，并没有课程授课分配/选课模型。初版学习统计限现有统一课程；将来多课程需新增教师课程授权和选课关系后才能隔离教师查看范围，不能宣称现有角色已提供多学校隔离。

## 13. 迁移与兼容方案

- 实施前检查实际数据库和Git改动，停止或协调写入，使用现有成套备份及恢复工具验证备份。
- 优先在数据库副本迁移演练，使用版本化增量迁移；保留旧表、ID、资料关联、用户、会话及旧文本，不重跑演示数据覆盖正式内容。
- 旧知识点生成“旧版正文”内容块并建立初始修订；section_id允许为空，先挂在章下的“未分节”位置，教师后续整理。
- 旧已发布正文保留原可见性，不因新的10模块校验一次性下架；新正式教案发布需满足新标准。旧内容“旧版待完善”要标清楚。
- 新字段支持旧API读取，教师旧保存接口在迁移期间明确桥接到草稿逻辑或只读并提示升级，禁止它绕过新发布流程直接覆盖上线内容。
- 旧lab_path转为受控FCFS关联，旧资料关联保留；旧题保持单选。旧本地“最后访问”可作为阅读位置建议，不迁成已掌握。
- 失败回滚事务；涉及文件的迁移保留原文件与引用。在验证知识点数、正文摘要、资料hash、所有者、作答数量前后相符后才切换。
- 如果必须破坏性迁移、删库、更换整体框架/大量依赖，应暂停单独说明；本方案不需要这些操作。

## 14. 实施阶段、文件范围与工期判断

完整覆盖包含内容平台、题库升级、6组可交互模板，不是一次改UI可以完成。按一名本科开发者在现有基础上实现并测试，建议预留4—6周，依内容审定和实际投入调整；不是保证日期。下周应先完成底座和一条真实学习闭环。

| 阶段 | 预计工作量 | 主要修改/新增范围 | 阶段验收 |
|---|---|---|---|
| A 需求与原型冻结 | 1—2天 | 本文、内容块样例、页面线框、动画输入/状态规格 | 12点覆盖、信息架构与边界确认；无业务改动 |
| B 数据/版本底座 | 2—3天 | migrations.py、teaching.py、learning.py；新增内容/版本服务和测试 | 备份恢复、旧内容不丢、草稿与发布隔离、权限测试 |
| C 教师/学生内容工作台 | 3—5天 | Knowledge.tsx两端、api.ts、Markdown.tsx或成熟渲染器、style.css；新增块编辑/渲染组件 | 教师创建带图表/案例的点并发布，学生真实阅读，修改草稿不影响线上 |
| D 题库/学习闭环 | 3—5天 | Practice.tsx、teacher/Questions.tsx、learning.py；作答/进度服务 | 四类题型、匹配分类承接、结果入库、返回原块、学习状态不造假 |
| E P0互动模板 | 5—8天 | 新增interaction引擎、播放器、4组组件、参数表单和规格测试 | 四重点知识点可调参、单步、回放、对照、状态守恒 |
| F P1与其他轻量交互 | 3—5天 | 分层/资源图、异步引擎、视角/目标/角色/历史图表模板 | 其余知识点功能完整，数据与来源真实 |
| G 联调、恢复与交付 | 2—3天 | 浏览器验收、测试、说明文档、Windows启动手册 | 全覆盖验收、旧FCFS/资料/认证回归、备份恢复 |

阶段可有重叠，不能将表内全部人日宣称一周完成。下周建议顺序：第1天确定结构和样例，第2天迁移与版本，第3—4天教师编辑/学生阅读，第5天一个P0场景的最小真交互与练习往返，第6—7天联调修复。若完整多题型或播放器尚未完成，要据实交接，不以静态占位宣称全部交付。

第一条样板建议1.1.5：它同时检验内容块、图片/来源、空分与时分参数、状态/事件、练习关联和进度。可先用虚构的“演示数据”验证结构，正式教案经教师核对后再录入，不把开发示例标为正式教材。

## 15. 用户需要准备的资料

### 可立即开始平台设计，不必等待齐全

- 原教材105MB文件继续保留本地/受控资料存储，不提交GitHub，不为做需求分析要求再次上传整本。

### 正式录入/发布前必需

| 资料 | 最小要求 | 不齐时如何处理 |
|---|---|---|

| 教材本节对应页 | 版次、印刷页和PDF页序、图号 | 教师可在表单补引用，不猜页码 |
| 图表原始数据 | Linux2.6.27分类数值、统计口径、日期/来源 | 不画精确分类图，不做跨版比较 |
| 每类交互规格 | 输入、默认值、范围、状态、事件、预期结果、简化假设 | 先用审定样例，禁止随机效果顶替 |
| 题目及解析 | 单/多选、判断、简答要点、知识点/块关联 | 用现有12题做题型验证，正式掌握标准待审核 |
| 图片/示意图 | 清晰原图或可重绘结构、出处、使用权限 | 工程可重绘教学图，不直接复制无来源第三方成果 |
| 学习评价规则 | 必做互动、题组、合格条件、自评/教师评阅方式 | 初版只报告完成情况，不虚构掌握结论 |
| 教师维护范围 | 负责老师、审核人、发布责任和更新频率 | 少量固定教师即可，不强建复杂审批流 |

来源中的教学比喻、术语口径、系统调用边界、虚化/抽象区别和并发/并行示例应由教师审定。开源图解/代码若后续借鉴，需要逐项检查许可证、版本、原始链接和适配方式；本报告没有进行外部GitHub资料检索，不能声称已有第三方实现可直接接入。

### 15.1 为每个互动准备的最小规格卡

统一填写：教学目标；模板ID/版本；初始状态；可操作参数及范围；合法事件/状态转换；两组以上输入—预期结果；每步解释；何种操作算完成；简化假设；无效输入提示；重置/回放规则；来源。可以由工程师协助把教案叙述整理为规格，教师只需审定，不要求教师自行设计数据协议。

例如竞争实验至少提供：A全执行后B执行结果2；A/B都读0再各写1结果1；有锁时同样输入结果2。异步实验至少提供两种合法时序和一种“先完成后请求”的非法时序。拿这些精确样例验收，才能避免动画看似合理但原理错误。

## 16. 完成判定与本轮交付

完整升级验收必须同时满足：

1. 教师无需改代码，能独立新增、修改、排序、配置、预览、发布、撤回、回滚一个完整知识点。
2. 学生能按章/节学习所有12点；各点的必需模块与教案映射无遗漏。
3. 六组重点互动及其余轻量互动都有真实行为，参数变更可产生正确、可解释、可复现的差异。
4. 所有正式练习进统一练习板块，教案所需题型可作答和保存；返回知识点定位正确。
5. 四项学习状态有明确证据与版本，刷新和后端重启不丢，不能把观看当掌握。
6. 草稿不泄露、个人数据不越权、教师更新不破坏已发布版本与历史作答。
7. 新旧资料、账号、FCFS与其他已实现功能回归通过，迁移/成套恢复验证通过。
8. 缺资料、故障、权限、网络失败、并发编辑都有明确处理；无只画页面不实现的关键按钮。

本轮只完成源码分析与需求文档。尚未开发新内容块、小节、模拟器、新题型或学习记录，也未进行数据库迁移。下一阶段先审定一个知识点的内容样板和交互精确规则，再按阶段实施；不需要重新选框架或另建前端。
