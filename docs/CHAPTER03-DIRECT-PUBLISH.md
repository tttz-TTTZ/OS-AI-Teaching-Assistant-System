# 第三章一键应用并发布

> 后续更正：平台实际采用第四章、4.*目录及拆分后的13单元，见[第四章迁移与页表拆分](CHAPTER04-LOCATION-FIX.md)。本文保留先前阶段记录，当前行为以最新更正为准。

2026-10-22，用户明确授权：“直接全部发布，不要我审核”。这取代第三章第一批的逐项审核要求。教师仍保留修改、单项发布和撤回权；不新增启动自动导入，不猜目标章节。

## 使用

更新 `feat/development-foundation` 并重启前后端。教师进入“知识点内容”或“课程目录”→ **第三章一键发布**（地址 `/teacher/chapter-content/chapter03`）：

1. 进入“选择目录，一键发布”，选择真实的存储管理目标章；存在目录冲突时明确映射已有小节。
2. 点击“检查目标与目录”，随后点击 **直接应用并发布全部内容**。一次发布12个知识单元和它们所用的章、小节，不要求逐个审核。
3. 如果已在上一版导入草稿：选择原目标章，进入第三步，点 **直接发布已有全部内容**。直接使用现有草稿中的修改，不重填覆盖。
4. 学生在知识点学习中选择实际目标章即可阅读。以后需要修改，在第三步进入原编辑器保存、发布即可。只想保存草稿的替代路径仍保留。

本轮不能从云端替用户操作Windows本地数据库，仍须明确本机真实目标。运行命令沿用 [第一批启动说明](CHAPTER03-FIRST-BATCH.md#windows启动)。没有新依赖或数据库迁移。

## 数据与发布规则

- `/api/teacher/chapter-content/chapter03/publish` 后端教师鉴权，学生调用403。不会代为发布尚未公开的整门课程。
- 先调用原成套备份机制，保存数据库与受控文件到数据库目录 `backups/before-chapter03-publish-*`；备份失败不进入写事务。
- 复用原导入登记和不可变修订。导入、新目录、本包当前草稿校验和发布在同一事务内；末条失败也整体回滚，不留下部分学生可见内容。
- 仅发布包内12个单元和当前所用小节。已有草稿使用当前内容，不改标题/正文/归属/页码，不归档旧知识点，不修改其他章、资料、正式题和个人笔记。
- 原预填JSON及其哈希保持不变，兼容上一版已导入登记。不同目标、不同包版本、跨章移动或已归档内容均不静默接管。
- 一次成功后登记 `direct_published`。重复调用不重新发布后来撤回的内容、不覆盖之后修改；后续更新由单项编辑器显式发布。此标记记录曾执行一键发布，实时可见性以单项当前状态为准。
- 仍保留28项待核实问题，不伪造教师逐项审核记录。只有静态图示，未新增存储管理算法/动画，不把FCFS/RR映射成页面FIFO/CLOCK。

## 修改与验收

`backend/app/chapter03.py` 提取事务内导入函数并增加备份/校验/幂等一键发布；教师第三章页与目录入口增加直接发布按钮、已有草稿发布和状态文案。分析报告、内容包、第一/二章规则不变。

新增4项回归覆盖：12单元立即可见及真实备份、保留当前人工修改、重复发布不恢复撤回项、末条失败全事务回滚、未公开课程拒绝与备份失败阻止写入。浏览器走真实“直接发布已有全部内容”按钮，验证12项全部可见，并继续图示/笔记/AI入口检查。

复现：

```bash
.venv/bin/python -m pytest backend/tests -q
npm --prefix frontend run build
.venv/bin/python scripts/verify_v02.py --chapter03-only
```
