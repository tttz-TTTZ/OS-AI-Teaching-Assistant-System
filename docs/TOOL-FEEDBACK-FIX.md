# 导图与闪卡点击反馈修复

## 问题与范围

导图和闪卡使用分批知识提炼流程：检查服务 → 预览资料 → 确认范围与调用次数 → 生成。其他工具使用普通生成流程。

原来的确认区、错误提示都位于可独立滚动的对话区顶部。阅读长对话后停在底部，点击工具不会把确认区滚到视野中，用户可能认为点击没有反应。这条路径不会产生 JavaScript 异常，未确认时也不会发送 generate 请求。

这是代码中已确认的可见性缺陷；尚未远程核对用户本机的具体请求，不能据此排除本机接口错误、资料超限等其他原因。

## 修复

- 开始处理、出现错误或收到提炼计划时，将反馈区滚入视野。
- 等待确认时聚焦确认区，明确说明将生成导图还是闪卡。
- 学习工具区显示等待确认状态，并提供“查看提炼计划”按钮。
- 开始其他工具任务时清理旧计划；后端未返回提炼计划时明确报错，避免停在没有确认按钮的状态。
- 保留确认后调用模型的规则，不自动重试、不修改数据库或已有学习成果。

## 验证

运行 `npm --prefix frontend run build` 和 `.venv/bin/python scripts/verify_v02.py`。

浏览器验收使用独立临时数据库、随机账号、模拟模型：

1. 构造长对话并滚到底部，分别点击导图和闪卡。
2. 在自动化点击确认按钮之前，检查确认区实际位于对话可视范围内并已获得焦点，避免测试工具自动滚动掩盖问题。
3. 验证未确认前没有发出生成请求；确认后导图、下载和闪卡翻面可用。
4. 模拟预览成功却缺少提炼计划，检查出现可见错误，并能继续使用其他工具。
5. 保留既有桌面、窄屏、权限、历史恢复和其他功能回归。

## 本机更新

在项目根目录执行 `git pull --ff-only`，保持前端开发服务运行，浏览器按 Ctrl+F5 刷新。生产构建方式运行则需重新构建并部署前端。

选择资料，点击“思维导图”或“知识闪卡”，检查“确认完整提炼范围”，点击“确认开始小节提炼”。超出 120 页或 12 批等限制会显示具体错误，应调整资料范围。

如果仍没有任何反馈，在网络面板查看 `/api/student/personal/status` 和 `/api/student/personal/sources/preview` 是否发出及返回内容。分享时隐藏 Cookie、Authorization 和密钥。
