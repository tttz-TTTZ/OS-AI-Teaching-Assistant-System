# 导图与闪卡：单次点击生成及可见反馈

## 当前交互

勾选资料并选好学习等级后，点击“思维导图”或“知识闪卡”即可生成，无需再点“确认开始小节提炼”。

完整流程：点击工具 → 自动检查服务 → 自动校验范围并获取提炼计划 → 分批提炼 → 生成并保存。后台分批整理知识的能力保留，前台不再设置额外确认页面。

## 改动

- 移除等待确认状态、确认区域及“查看提炼计划”入口。
- 移除“已选来源与页码范围”及重复移除按钮，仅保留资料列表勾选；新请求使用整份资料。历史记录的原始范围和依据保留，恢复历史后新请求不会沿用隐藏的旧页码范围。
- 一次点击使用本次资料范围、主题和等级完成校验及生成，保留生成进度显示。
- 内部 `analysis_confirmed` 字段保留为兼容现有后端协议：前端成功取得提炼计划后自动设置；它不再代表用户进行了一次额外点击。
- 保留后端页数/批次限制、权限、指纹一致性检查、任务幂等与失败后手动重试。
- 开始处理或出现错误时，仍自动把反馈区滚入视野；缺少提炼计划时明确报错。
- 不修改数据库或已有学习成果。

## 背景

先前的确认区位于可独立滚动的对话区顶部。阅读长对话后点击工具，确认区可能藏在屏幕外，用户会认为点击没有反应，且没有 JavaScript 异常。上一版增加了滚动和提示；本次依据用户要求进一步取消二次确认。

## 验证

运行 `npm --prefix frontend run build` 和 `.venv/bin/python scripts/verify_v02.py`。

浏览器验收使用独立临时数据库、随机账号和模拟模型，无真实模型费用：

1. 长对话滚到底部后，单击导图直接生成，且只发出一次生成请求。
2. 单击闪卡直接调用生成；失败后仅在用户点击重试时重新生成。
3. 校验等级参数保留，导图图片及下载、闪卡翻面正常。
4. 模拟缺少提炼计划，显示可见错误且不发出生成请求。
5. 四份实际 PPTX 上传后，单击导图、再单击闪卡，检查知识提炼、批次缓存和报告结果。
6. 检查取消勾选后不会生成，恢复带旧页码的历史后，新生成请求使用整份资料。
7. 保留既有桌面、窄屏、权限、历史恢复及其他功能回归。

## 本机更新

在项目根目录执行 `git pull --ff-only`，保持前端开发服务运行，浏览器按 Ctrl+F5 刷新。生产构建方式运行则需重新构建并部署前端。

超出 120 页或 12 批等限制时会显示具体错误，减少勾选资料或拆分课件后上传即可。
