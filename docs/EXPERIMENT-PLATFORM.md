# 算法实验平台：教师与学生工作流交付

日期：2026-10-20（接续 10 月 16 日的升级方案）。沿用 React / FastAPI / SQLite，以用户确认的“独立算法实验 + 知识点关联 + 教师配置教学内容”方案增量升级。

## 现状、目标与实施范围

升级前只有独立 FCFS 输入和结果页，没有实验教学模型、发布版本或学生实验记录。开始时 Git 工作区干净；基线后端 55 项通过。只读检查工作区数据库有 7 个章节、7 个知识点、1 份资料及已有迁移标记，未删除或改写这份数据。用户 Windows 数据不在云端，不能声称已检查过用户电脑的数据库。

本轮提供 FCFS、非抢占 SJF、RR 三种可靠调度模板。教师用已有算法建立多个教学实验，维护目标、说明、观察任务、参考说明、默认输入、课程章节及知识点关联。学生在独立实验库操作，保留知识点中的概念演示。一次运行的动画、事件解释、结果表与指标来自同一次后端计算。

教师维护教学内容；新增算法程序仍需开发、验证，并更新模板和输入组件。不会让教师上传执行代码。本轮不是覆盖七章全部算法，也没有自动评分、班级实验统计或同屏多算法比较。

## 教师动线

**算法实验管理 → 新建教学实验 → 模板与归属 → 教学任务 → 示例输入 → 试运行与发布**。

| 页面 | 专注完成的任务 |
|---|---|
| 实验列表 | 查看草稿/已发布/有未发布修改，选中一项继续编辑 |
| 模板与归属 | 选择 FCFS/SJF/RR，修改标题和章节，关联一个或多个知识点 |
| 教学任务 | 分别编写目标、操作说明、观察问题、参考说明，支持基础 Markdown |
| 示例输入 | 配置进程及 RR 时间片，可用三个示例：一般到达、包含空闲、同时到达 |
| 试运行与发布 | 用当前已保存示例实际计算，查看事件回放与指标，再确认发布或撤回 |

- 首次建立后点击步骤会先保存；保存失败不切换。可手动保存，页面提示草稿不等于发布。
- 当前教师必须成功试运行**当前草稿修订**才能发布，后端也检查；修改后重新试运行。目标/说明/任务缺失、所属课程或章节未发布时拒绝发布。
- 教师改草稿不改变学生正在使用的发布修订。并发编辑返回 409，避免覆盖其他页面的更新。
- 未保存编辑按账号与实验保存在本标签会话缓存；刷新可恢复，服务器版本不符会提示核对。缓存不是数据库，关闭标签或浏览器清理不能保证恢复。
- “重新读取”在存在未保存编辑时要求确认。返回列表会尝试保存。
- 初始不自动创建或发布课程实验。**更新后请先由教师新建并发布第一份实验**；学生空列表是明确的未发布状态。默认文字与示例标为演示，需要教师审核。

## 学生动线

**实验库 → 阅读任务 → 动手运行 → 回放并分析 → 保存观察 → 返回知识点或继续学习**。

1. 实验库按算法、章节、标题筛选，只显示学生可见的已发布实验；最近运行单独列出（默认展示最近 20 条，旧记录不自动删除）。
2. 进入先读目标、操作说明和观察任务，不在说明页混入输入表与结果。
3. 动手运行时载入教师示例，可增删进程、调整数值、恢复示例。运行成功即保存本次输入、结果、教学修订和引擎版本。
4. 结果提供甘特图、逐事件前后步、自动回放/暂停、事件滑块和选择原因；指标包含等待、周转、响应时间及 CPU 利用率。
5. “观察与记录”单独填写自己的分析。已运行且提交非空观察才标为“已保存观察”；不是自动判对，也不标记掌握。
6. 本人历史运行可刷新重开，保留当时教学任务、输入、结果与观察，即使实验后来撤回。其他学生和教师的本人记录接口不能读取它。
7. 知识点“开始学习”和“相关资料”显示配套实验入口，进入携带原知识点与模块，实验可返回原位置。原 `lab` 标记保留为 FCFS 分类入口，新实验关联在实验管理维护。

修改输入后，上一次结果保留并明确标记“输入已修改，尚未重新运行”，不混淆新输入与旧结果。切换实验任务暂停动画并保留本页现场。未保存观察离开有确认；输入按标签/账号/实验/修订暂存，观察按账号/运行暂存，未保存观察可从历史运行页恢复。正式保存后进入数据库。课堂主导航或浏览器关闭行为受浏览器能力限制，不能以会话缓存替代后端保存。

## 算法约定与边界

- 三种模板都是单 CPU 教学模型，无 I/O、抢占优先级或上下文切换开销；时间单位需统一。
- FCFS 非抢占，按到达时间，同到达按输入顺序。
- SJF 非抢占，在当前就绪集合中选择最短运行时间，同长先到达、再按输入顺序；不会预知未来进程。
- RR 时间片边界将新到达者先入队，再将未完成当前进程放到队尾。最后不足一片即完成。
- 最多 100 个进程；进程名去空格后唯一；时间必须有限、到达非负、运行和时间片大于零，上限 1000000。RR 预计超过 2000 个片段时拒绝，避免无界运算与页面卡顿。
- 等待 = 完成 − 到达 − 运行；周转 = 完成 − 到达；响应 = 首次开始 − 到达。CPU 利用率的总时长包含从时刻 0 起的初始空闲。
- 时间轴短段有最小宽度，数值为准；这是调度事件回放，不是逐时钟的就绪队列仿真。
- 历史 `POST /api/labs/fcfs` 仍保留，兼容原客户端与测试。

## 数据设计与迁移风险

V5 只新增以下表与索引，不重建旧表、不删除课程/文件/账号/学习记录，不自动匹配教材章节。

| 表 | 用途 |
|---|---|
| experiments | 实验实体，草稿/发布修订指针与编辑版本 |
| experiment_revisions | 不可变教学内容快照，含章节、知识点 ID 集合、算法、默认输入 |
| experiment_previews | 哪位教师试运行过哪个草稿，发布前检查 |
| experiment_runs | 本人运行输入/结果、教学修订、引擎版本、观察与保存时间 |

知识点 ID 集合随内容修订存储，写入时验证引用；学生输出过滤不可见知识点。文件仍沿用原受控目录，实验结果只存数据库。备份脚本完整备份 SQLite，所以实验表与原资料元数据一起保存。

已有 V4 升级前自动备份到数据库旁 `backups/before-v5-*`，包含数据库与 uploads，备份失败则停止迁移。更旧版本在同次升级已有的 V2/V4 前备份基础上继续追加 V5，避免重复复制教材。迁移处于事务中，版本标记防止重复执行；再次启动不重复建表。应预留足够空间存放数据库和上传文件的备份，并保留可恢复副本。不要为了启动去删除数据库。

撤回阻止新的学生详情/运行；旧运行快照只允许本人查看。发布版本已改变时，旧页面提交运行返回 409，不偷偷换用新算法或新任务。没有引入新依赖、数据库服务或云存储。
